§1橋本CEO の発言・指示パターン 15項目

PATTERN 01
判断基準は常に「相手から見てどう見えるか」
自分視点ではなく 顧客・読み手の感じ方ベースで品質を判定する。商談相手・経営者の目線で「この資料は通用するか」を即座に評価。 「失礼だよ」「詐欺になる」「誤解を誘う」「相手の社長は納得しないよ」
PATTERN 02
質問形式 = 暗黙の指摘
直接命令を避け、質問の形で考えさせる。質問が出た時点で「不要」「変更必須」のサインと読む。 「これ何で書いたの？」「価格方針とかいるの？」「投資回収10ヶ月は長すぎると思わないか？」
PATTERN 03
専門用語・抽象語を即排除
業界・社内用語が顧客にとって 意味不明である状態を許容しない。即「平易な日本語に置き換えろ」と要求。 「直接効果という言葉の意味がわからない」「能動型は正しい日本語じゃない」「ロールはわかりづらい」
PATTERN 04
論理整合性に厳しい
計算根拠・前提条件の論理破綻を即指摘。保守シナリオ併記など「逃げ道」を嫌う。 「テキトーなこと書くな」「論理的に説明しろ」「払ったお金はすべて投資費用」
PATTERN 05
冗長・過剰装飾を嫌う
必要最小限の表現＋必要な情報密度のバランスを要求。装飾過多や情報過多はマイナス。 「目立たせるな」「気持ち悪い」「細かく資料にしろとは言ってない」「セクション1ページは余白多すぎ」
PATTERN 06
具体性・固有名詞ベースで指示
抽象論ではなく 数値・固有名詞で根拠を担保。曖昧な表現はリジェクト。 「店長層 月給29万円・時給1,800円」「店舗あたり従業員5名×30分面談」「ディライトカンパニー仙台の求人」
PATTERN 07
連続指摘・流れる修正
1指示が反映されている間に 「あと〜」「ついでに〜」と次々追加。一括修正よりも逐次フィードバックを高速回転。実装側はコンテキストスイッチに耐える必要あり。
PATTERN 08
代替案も自ら提示
否定だけでなく 具体的な解決の方向を提示。実装者の判断を待たない。 「黒い箱と太い下線でいい」「グレーで」「テーブル形式にして」「黒背景で結論」
PATTERN 09
経営者向け視点を最重視
結論先出しを絶対要求。文字密度・優先順位・即時可読性を最優先。 「経営者は時間がない」→ 黒バッジ「結論」、3行サマリ表で 5秒把握
PATTERN 10
整理整頓・運用視点
ファイルの存在意味を常に問う、不要物は即退避。仲間目線でのアクセス容易性も重視。 「古いhtmlは_oldに」「仲間が最新ファイルにすぐたどり着けるように」「重要なのは最新版では？」
PATTERN 11
配布・公開の主導性
配布手段・形式まで自ら指示。実装者に丸投げしない。 「GitHub Pagesにアップして共有リンクくれ」「PDF化しといて」「セクション=ページ整合で」
PATTERN 12
タイポ許容・本意伝達優先
入力速度を優先、文意は文脈から汲ませる。実装側は表記揺れに惑わされず本意を読む。 「わかりずらい」「市内で（しないで）」「ＰＤＦ」全角混在
PATTERN 13
「妥協しない・サボらない」を自ら体現
不完全な状態でアップしようとすると 即座に差し戻し。仕事の完成度に妥協を一切許容しない。 「不完全な仕事するな」「これ直してから」
PATTERN 14
検証可能性を要求
学習データ・推測ベースの数字を信用しない。WebSearch で実態確認、求人公開情報など外部の信頼ソースを根拠に求める。
PATTERN 15
「ね」「よ」のソフト語尾でも指示は明確
柔らかい語尾でも実行優先度は高い。「いれといてね」「直しておいてね」「しないでね」は即時対応案件。 「これ直してからアップしてね。不完全な仕事するな」

§2VAIZER 共通の対応原則（全員守る）

  • 結論先出し → 詳細。最初の3行で「何を提供して、いくらで、いつ」を伝える
  • 専門用語ゼロの平易な日本語。業界用語・社内用語は読み手目線で再翻訳
  • 数値・固有名詞ベースの根拠。「20店舗×3時間×¥1,800」レベルまで分解
  • 論理一貫性の自己検証。逃げ道・併記・保守シナリオは不要、主張を弱めるだけ
  • 冗長排除・必要最小限。装飾／情報量／余白は内容に応じて最適化
  • 即実行＋事後報告（確認を求めない）。ただし矛盾発覚時は即指摘・即修正
  • 顧客視点で再読チェック。送る前に「この資料、相手はどう感じるか」を必ず1回想像
  • 整理整頓を常に。古い／作業中ファイルはルートから退避、最新版だけが目立つ状態に保つ
